# Bad Time 战斗：沙箱窗口与游戏编辑器设置方案

适用文件：工作目录根部 `main.lua`，构建标记 `2026-10-08-review-3-text-pause-stab`。配置入口是 `lua/config.lua`。本方案按照已读取的官方客户端控件资料与本地官方教程编写；客户端资料镜像日期为 2026-09-25。具体面板在游戏版本更新后可能调整，可按文中的官方术语搜索。

当前交付的是 Lua 与画面配方，不包含已经导入游戏的控件模板、音效资产或服务器节点图存档。先完成下面的模板映射，静音试玩成功后再接音效和结算。

## 1. 两个窗口分别做什么

| 窗口 | 本项目要做的事 |
| --- | --- |
| 原神内的局内编辑器（游戏窗口） | 单人关卡、出生点、界面布局、客户端控件容器、客户端模板和脚本挂载、结算显示设置 |
| 千星沙箱窗口 | 把本地 main.lua 建立脚本映射；服务器信号声明、结算节点图；客户端脚本日志与调试 |
| 工作目录 | 改配置、构建 main.lua、运行离线测试；不修改父级知识库 |

战斗在客户端 2D 画布里运行，92 HP、KR、补给和攻击条由 Lua 管理。3D 角色生命值不会自动等同于战斗 HP。推荐把最大玩家数设为 **1**；这份客户端实现没有多人共享战斗、同步血量和独立多人结算协议。

## 2. 游戏窗口：关卡与主界面

1. 建一个单人关卡，在安全的地面上放置出生点，附近不放敌人、伤害区域和可触发传送的机关。避免 3D 角色在操作 UI 时受伤或离开出生区域。
2. 打开 **界面控件组管理 → 界面布局 → 添加界面控件 → 客户端控件容器**。
3. 选中该容器，进入 **画布设置 → 前往编辑**，在客户端画布中添加一个**容器节点控件**，命名为 `SansFightRoot`。
4. 把 Root 设置成覆盖画布：锚点最小 `(0,0)`、最大 `(1,1)`，位置与尺寸差异都为 0，缩放为 1，旋转为 0。父级的客户端控件容器同样覆盖主要显示区域，保持**激活且可见**。
5. Root 开启**显示常驻光标**、**屏蔽按键事件穿透**、**屏蔽区域内光标事件穿透**。代码也会设置这三项。不要在 Root 上再挂一份处理相同按键的脚本。
6. 关卡运行界面尽量只保留这一个全屏战斗容器；原有按钮、移动提示和其他全屏交互 UI 不要覆盖它。若保留系统菜单，测试关闭菜单后是否恢复正常输入。

画布可用 1280×720 作编辑参考，代码实际读取画布尺寸，将 **640×480** 逻辑画面等比居中，宽屏两侧自动留黑边。无需手动把每条骨头放进编辑器；它们运行时按需生成。不要把 Root 裁剪成小窗口，否则炮身、台词和终盘光束可能被截断。

官方规定客户端控件容器必须处于激活、可见状态，客户端控件与脚本才正常工作。关闭容器、传送、重连等过程可能重建客户端控件；本版没有持久化战斗进度，重新初始化后从标题页开始。[客户端控件容器](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhlz2lrly3dq)、[客户端控件和客户端脚本](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhbgxf0nynww)

## 3. 游戏窗口：建立 CodeArt 所需模板

入口为 **界面控件组管理 → 界面控件组库 → 客户端控件模板 → 添加客户端控件**，制作后**存为模板**。必须保存为可动态实例化的模板根节点；主屏里已摆放控件的索引、模板内子节点索引和运行时 id 都不能替代它。[官方模板调用规则](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhbgxf0nynww)

推荐做 8 类模板。图片、文本、光标可直接作为模板根；若编辑器采用容器包装，就做“一个容器节点 + 唯一一个对应叶子控件”，配置里填**外层根节点索引**。适配层会寻找叶子控件，并激活、拉伸包装层。保持模板简单，不添加装饰、脚本、遮罩或额外按钮。

| 配置键 | 推荐名字与控件内容 | 必须设置 |
| --- | --- | --- |
| `rect` | `CA_Rect`，图片控件中的纯白实心矩形 | 图片为完整纯色块；颜色白、alpha 255；无羽化、无遮罩、不使用填充裁切 |
| `rot` | `CA_RotRect`，同样的实心矩形 | 可复制 rect；旋转与位置由代码控制 |
| `circle` | `CA_Circle`，纯白实心圆 | 用于骨头端帽；图形周围不要有大透明边距 |
| `rtri` | `CA_Triangle`，纯白三角形 | 未旋转时尖朝上；保留给其它三角图元；骨刺使用细骨排列 |
| `ring` | `CA_Ring`，纯白圆环 | 用于触摸摇杆；不要误选实心圆 |
| `text` | `CA_Text`，文本框控件 | 背景完全透明，白字，支持中文；无外框；固定字号，不启用自动压缩字号 |
| `cursor` | `CA_Cursor`，光标检测区域控件 | 可被光标射线检测；无可见装饰 |
| `baked/bakedC/bakedRoot` | `CA_Container`，空的容器节点控件 | 这三个键可共用同一个模板索引；无背景、子控件、脚本、裁剪 |

各模板根与所用叶子设置激活、可见，缩放 `(1,1,1)`、旋转 0。图片使用基础完整显示方式，清空软边和填充裁切。矩形模板要能被拉伸到 1 px 小块及全屏尺寸。若父层有内边距、网格布局或自动布局，先移除；否则 CodeArt 的比例锚点会偏移。

将每类模板的**控件模板索引**抄入 `lua/config.lua` 的 `C.templates`。文件中的模板索引来自当前工程配置，新工程不能照抄。

`C.images` 默认全部为 **0**，表示沿用模板中选择好的矩形、圆、三角、环。如果确实需要运行时替换，才填写在当前工程中已验证的图片资产 ID。外部模拟器使用的 `100001` 等编号没有被本次资料确认成官方通用资产，不能直接当成真机图元编号。

Sans、龙骨炮和灵魂不需要另行导入角色 PNG。它们由纯色小块组合，Sans 的子控件只在首次使用某姿态时创建，后续复用；密集旋转龙骨炮采用较粗的 LOD。全部元素和图元数量见 [CodeArt 说明](CodeArt说明.md)。中文剧情与按钮文字由 lua/textart.lua 的矩形字形显示，不依赖文本模板。

## 4. 沙箱窗口：脚本映射与挂载

1. 打开 **客户端脚本资源管理器 → 客户端脚本映射文件夹**。
2. 在文件夹内右键 **新建脚本映射**，命名 `SansFight`，通过编辑文件路径关联工作目录的 **main.lua**。
3. 回到游戏窗口的 `SansFightRoot`，在**脚本**页签点击**添加脚本**，选择刚创建的 `SansFight` 映射。
4. 只挂在 Root 一处。不要给 rect、Sans 身体容器、光标区和外层服务器客户端控件容器再次挂载 main.lua。
5. 保存工程后重新进入试玩。确认日志出现 `main start: build=2026-10-08-review-3-text-pause-stab`，且 `mode=core`。

根目录 main.lua 已内嵌全部模块，正式工程不需要为 `lua/core.lua` 等分别建映射。只在本地保存 Lua、没有建立沙箱映射的文件不会被上传。每次修改 `lua/config.lua` 或源码后运行 `python tools/build.py`，保存映射对应文件，再结束当前试玩并重进，确认构建标记与预期一致。[官方脚本映射与上传规则](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhbgxf0nynww)

默认 `C.updateCallback='level'` 使用 **OnLevelUpdate**，与关卡暂停一致。官方同时提供 OnUpdate 和 OnLevelUpdate，不能把两者都推进战斗。只有外部宿主确认仅调用 OnUpdate 时，才改成 `'ui'`；不要在正式工程自行转发一遍更新。[客户端控件 API](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhtakr07vej4)

## 5. 操控与玩法

| 场景 | 键盘与鼠标 | 触摸 |
| --- | --- | --- |
| 标题页 | 左右方向键或 A/D 选难度；Z、J、空格确认；也可点击难度卡开始 | 点击难度卡选中，再点同一卡开始 |
| 红魂 | WASD 或方向键自由移动；按住 X/退格减速 | 敌方阶段在左半屏按住、拖动，出现浮动摇杆 |
| 蓝魂 | 与重力相反的方向键起跳，也可用 Z/J/空格；长按跳得高，松开变小跳；垂直于重力方向的键移动 | 将摇杆拖向反重力方向起跳；持续保持方向为高跳，松回中心/松手截断 |
| 四项菜单 | 左右选中；Z/J/空格进入；鼠标单击直接选中并确认 | 第一次点选中，同一项第二次点确认 |
| 子菜单 | 上下选项；确认执行；X/退格返回；点面板外也可返回 | 二次点选确认；点面板外返回 |
| 攻击条 | 按确认键或点击停止；6 秒未操作自动停止 | 点击一次停止 |
| 结局 | 左右选择结算或重开；确认；鼠标可直接点按钮 | 直接点结算或重开按钮；结局页空白点按会重开 |

蓝心尖端指向重力方向。尖朝下时按上跳，尖朝右时按左跳，尖朝上时按下跳，尖朝左时按右跳。红心保持尖朝下。取消键在战斗中用于慢走，在子菜单中用于返回。

正式键位通过官方语义按键绑定：方向键使用独立 CraftspersonKey，Z、J、空格分别注册。Enter/Esc 仅作为某些外部模拟器的可选别名，**本版不把它们承诺为官方确认/返回键**。鼠标左键只走光标 UI 点击，避免和“普通攻击键”同时确认两次。

手柄已绑定方向十字键、A 确认/跳跃、B 返回/慢走的官方语义事件，同时允许宿主提供 MenuConfirm/MenuBack。没有实体手柄实测；必须检查当前平台的实际映射与焦点。如果当前版本只派发导航事件而不派发这些按键事件，需要按官方手柄导航说明补充焦点接入。本版不会读取模拟器特有的摇杆轴值。

手机默认采用单触点浮动摇杆；其他触点不会夺走摇杆或提前释放它。当前没有独立的触摸慢走键或右侧跳跃按钮，菜单与摇杆随战斗阶段切换。可在 `C.device='mobile'` 强制检查触摸分支，正式建议 `'auto'`。

推荐难度为**原作**。原作档初始 92 HP，补给 8 次：奶油糖派 1（99）、方便面 1（90）、牛排 1（60）、传奇英雄 5（40），实际 HP 不超过 92。使用道具不清 KR。蓝骨在移动时伤人，橙骨在静止时伤人；白骨通常伤人。KR 最多 40，不能把 HP 烧到 0。

FIGHT 计数和下一份攻击脚本独立：吃东西、检查会进入下一轮弹幕，但不会累加 FIGHT。完成第 13 次 FIGHT 后进入中场，可以继续检查和吃补给；**确认饶恕会失败**，打开仁慈菜单或返回不会触发陷阱。再次 FIGHT 才继续第二阶段。23 次 FIGHT 后进入终盘弹幕，撑过后再攻击进入击倒结局。HUD 的 `FIGHT / 23` 表示阶段进度。

`easy/normal/hard` 为额外练习档；`trainingItems=true` 才启用旧版额外面包，并且只在非原作档生效。正式发布不要把练习档成绩与原作档混在同一个排名中。

## 6. 音效与 BGM

默认所有音效 ID 为 0，保证没有对应资产时可以静音运行。`game.PlayAudio2D(audioId)` 接收的是**已配置的音效资产 ID**，不是音效播放器实例序号、文件路径或脚本模板索引。[官方音频 API](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhtakr07vej4)

在游戏窗口选择可用的音效资产并试听，记录其实际 ID，填入 `C.audio`。需要使用音效播放器时，入口是实体/元件的组件页签 → 音效播放器 → 详细编辑 → 添加音效；可调音量、播放速度、循环与 3D 开关。**播放器的识别序号与音效资产 ID 是两件事**。本项目的短音效由客户端直接播放 2D 音频，不要求每个图元都添加播放器。[音效播放器](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhwiv89yra02)

| 配置项 | 触发时机 | 建议声音 |
| --- | --- | --- |
| `bgm` | 开局、重开、第二阶段继续 | 战斗音乐；中场与结局停止 |
| `menu/confirm/cancel` | 移动选项、打开菜单、返回 | 短促轻音，避免遮住战斗提示 |
| `hit/heal/jump` | 直接受伤、吃补给、蓝魂起跳 | 三种可分辨短音 |
| `blasterCharge/blasterFire` | 炮生成蓄力、进入发射 | 蓄力与发射区别明显；密集炮会限制重复短音 |
| `soulMode/slam` | 切换魂色、甩击方向生效 | 模式切换音与撞击提示 |
| `boneWarn/boneStab` | 骨刺预告、伸出 | 预告易辨认，伸出音较短 |
| `death/victory` | 失败、击倒或练习饶恕结局 | 一次性结束提示 |
| `scriptSoundFlash/Ding/GasterBlaster` | CSV 中对应 Sound 命令 | 按所用资产映射；与常规炮音重复时把其中一项设为 0 |

`bgmLoop=true` 在音频实例结束后重新播放，不能保证采样级无缝。若资产本身已循环，可按试听结果决定是否保留这一设置。中场会停止音频，进入第二阶段时从头播放，不是精确位置续播。脚本未提供客户端音量/播放速度接口，音量、混音和播放速度应通过实际可用资产设置或播放器方案控制；不要写不存在的 `SetAudioPitch`。

本次没有交付 MEGALOVANIA 或 Undertale 音效录音，也没有从官方资料确认外部 mp3 的通用导入流程。应使用当前平台允许的资产；原作音乐能否导入要按实际版本的资产功能和授权条件确定。代码保留旧版音符旋律，但默认 `useNoteMusic=false`，它是不完整的单音近似，不能当成完整原曲。若启用，需要为 `notes`/`pitchClasses` 配好各音高的实际资产，仅填一个 fallback 音效无法还原音高。

不要同时放一个自动循环的场景 BGM 播放器，又让 Lua 播放同一首音乐，否则会叠音，并且 Lua 无法停止它没有创建的音频实例。

## 7. 沙箱窗口：声明服务器结算信号

在**服务器信号管理器**添加 `SansFightSettle`，参数按下面**顺序和类型**声明，应用修改。参数名字可自定，顺序不能改；客户端 AddString/AddInt/AddFloat 按位置添加值。[信号配置](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhlaj0r9bldi)

| 顺序 | 建议参数名 | 类型 | 含义 |
| ---: | --- | --- | --- |
| 1 | outcome | 字符串 | `kill` 击倒；`fail` 失败；`spare` 非原作档饶恕 |
| 2 | hp | 整数 | 剩余战斗 HP |
| 3 | kr | 整数 | 剩余 KR |
| 4 | fightAttempts | 整数 | 累计 FIGHT 阶段计数，不是 CSV 执行次数 |
| 5 | elapsedSeconds | 浮点数 | 本次战斗经过的逻辑秒数，包含玩家行动时间 |
| 6 | damageHits | 整数 | 常规伤害命中次数；不包含 KR 自燃及直接撞墙扣血 |
| 7 | difficulty | 字符串 | `original/easy/normal/hard` |

本版只在结局页选择**结算**后发送。失败仍发送 `fail`，不会被改成胜利。重开只重置本地战斗，不触发游戏关卡结算。发送接口出错后每秒重试，最多 3 次；超过后显示失败提示，可再点击结算重试。接口返回成功只说明完成本地发送，不能证明服务器已经接收、执行结算；因此 UI 显示“等待服务器结束关卡”。

## 8. 沙箱窗口：服务器节点图连线

推荐创建服务器实体节点图 `SansFightSettlement`，挂在一个一直存在的控制物件上，避免物件被销毁或仅在某战斗阶段生成。

单人关卡的最小连线方案：

1. **接收信号**选择 `SansFightSettle`，读取上述 7 个参数。
2. 用**获取在场玩家实体列表**取得当前玩家，确认列表长度为 1，再取唯一的**玩家实体**。不要把控制物件自身实体或 3D 角色实体直接接到“玩家实体”引脚。查询节点名称见[官方查询节点](https://act.mihoyo.com/ys/ugc/tutorial/detail/mh65asiyhv2k)。多人时必须另行设计发送者识别与独立结算，本版的 7 个参数不包含玩家身份。
3. 控制物件创建布尔自定义变量 `SansSettled`，默认 false。接收时如果已为 true，就结束本次处理；否则检查 outcome 是否属于约定的三种值，并把变量设为 true。新的游戏关卡启动时恢复 false。信号是全局广播，只保留一处负责最终结算的监听。
4. outcome=`kill`：**设置玩家结算成功状态 → 胜利**。outcome=`fail`：同节点设为**失败**。outcome=`spare`：只有开放非原作练习饶恕时设为胜利；正式原作规则建议按失败处理，并单独显示“饶恕练习”。
5. 可选：用**设置玩家结算计分板展示数据**显示最多 3 条数据。建议顺序 0“难度”字符串，1“战斗时间”浮点数，2“FIGHT 次数”整数。该节点最多显示三条。[官方执行节点](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhw66orrrfkm)
6. 如需展示排名，接**设置玩家结算排名数值**。该节点接收整数，计时可取 `floor(elapsedSeconds * 1000)`；小值在前适合通关计时。单人初版也可以完全关闭排名。客户端上报的统计适合本地娱乐展示，不能直接当作多人权威排行榜验证。
7. **最后**执行**结算关卡**。必须先设置玩家胜负状态和展示数据，再结算。该节点会结束整个关卡。[关卡结算](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhx1du08nhwo)

可按以下顺序核对节点图，不要求导入某种伪代码文件：

```text
接收 SansFightSettle
  → 检查单人玩家与 SansSettled
  → 检查 outcome，设置 SansSettled=true
  → 按 outcome 设置玩家结算成功状态
  → 设置最多三条结算展示数据
  → 可选设置整数排名数值
  → 结算关卡
```

关卡重开与 Lua 的“重开”不同：Lua 重开仍在同一个游戏关卡内，`SansSettled` 不应因普通吃药、点击菜单而改变。服务器一旦调用结算关卡，本次游戏结束，下一次进入时重新初始化变量。

## 9. 游戏窗口：结算显示与可选变量

进入系统菜单 **关卡设置 → 结算**，选择**个人结算**。初版关闭游戏内排名；确认胜负正常后再启用。通关计时排名选**由小到大**，生存进度排名选**由大到小**，并配套调整上面的整数排名数据。不要把这两种指标混用。[官方结算设置](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhx1du08nhwo)

可选的关卡全局自定义变量：

| 名字 | 类型/默认值 | 作用 |
| --- | --- | --- |
| `SansDifficulty` | 字符串 `original` | 覆盖配置文件的标题页默认难度；玩家仍可在标题页改选 |
| `SansRound` | 整数，通常不设 | 仅 `C.debug=true` 时使用的阶段跳转；正式发布保持 debug=false |

调试跳转的 1 表示第一份常规攻击，13 为中场，14 为第二阶段开始，23 为终盘；正常默认从见面杀开始。该数值代表阶段/FIGHT 进度入口，并非任意“第 N 个 CSV 行”。调试关卡可以在进入标题页后设值，然后确认开始。调试模式并不自动无敌，正式玩家流程也没有无敌开关。

## 10. 真机验收顺序与排错

在沙箱日志中勾选**客户端脚本**，确认选择，运行时双击错误条目查看详情。若普通日志无法报告加载卡死，官方资料说明可检查脚本本地存储位置的 `ErrorLog.txt`。[客户端脚本日志](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhbgxf0nynww)

| 检查 | 合格表现 | 不合格时先看什么 |
| --- | --- | --- |
| 启动 | 标题页 4 档难度，`mode=core`，无模板实例化错误 | 映射是否关联根 main.lua；Root 是否只挂一次且激活；模板是否已存为客户端模板 |
| 图元 | 黑底、白框、完整 Sans、像素心，炮没有方形白底 | 模板实际图片、透明边距、遮罩/填充、父层缩放与裁剪 |
| 键盘 | WASD/方向键均移动；松开一个同方向键仍保留另一个；Z/J/空格只确认一次 | 按键监听日志；容器事件穿透；其他 UI 抢占 |
| 鼠标 | 点标题、菜单、子行可操作；拖动不会移动灵魂 | showCursor；光标模板；客户端容器可见与层级 |
| 手机 | 上拖确实上移；松手停止；第二触点不能夺走摇杆；菜单二次确认 | device 分支、touchId、光标坐标；控件层裁剪 |
| 蓝魂 | 短按与长按高度不同；左右/上下重力方向均可跳；站平台与框边一致 | 四向心尖；平台模板；不要另写一套按住跳跃物理 |
| 攻击结束 | 骨头、平台、激光清掉，进入菜单 | 脚本 EndAttack、旧 main.lua 是否仍被载入 |
| 中场 | 可多次补给；打开仁慈不死，确认饶恕才失败；攻击继续 | FIGHT 计数与 SansRound；不要用普通点击直接结算 |
| 音效 | 菜单、受伤、炮蓄力/发射可辨；中场与结果停止 BGM | 资产 ID 与播放器序号混淆、BGM 叠放、0 静音配置 |
| 失败结算 | 选择结算后服务器显示失败 | 信号参数顺序、玩家实体引脚、胜负先于结算关卡 |
| 击倒结算 | 终盘后攻击，选择结算，服务器显示胜利 | kill 分支、节点图挂载、SansSettled 初始化 |
| 重开/暂停/退出 | 重开恢复 92 HP 与补给；暂停不推进弹幕；退出无残留音效 | 更新入口、重复脚本、生命周期日志 |

先用静音模式完成启动与输入，再接 1 个菜单音、1 个受伤音，最后接 BGM 和全部炮音；先验证 `fail` 结算，再通过调试入口验证终盘 `kill`。服务器成功结算后再测试正式从见面杀开始的完整流程。

还要检查 16:9、较宽屏和手机比例；角色脚底、UI 显示边界与碰撞框应一致，不能出现框已经缩小但灵魂还按旧框行动。官方控件预算和不同设备负载本次没有真机数据，密集终盘需要在目标设备观察负载；控件会缓存复用，不要为每帧再创建另一套图元。

## 11. 复刻范围与已知差异

攻击数据参考 [Jcw87/c2-sans-fight](https://github.com/Jcw87/c2-sans-fight) 的 Battle.xml 与 24 份 CSV。本版恢复了参考项目主要攻击时序、FIGHT 阶段门控、补给、中场陷阱、蓝魂和 KR。参考项目自身也说明平台加速、命中框和对话存在差异，不能据此宣称与 Undertale 原版完全相同。

本版仍有这些明确差异：第二阶段菜单骨头攻击未接入；最终攻击后的睡眠、推框与自动第二刀没有还原，改为再次 FIGHT 进入击倒结局；部分对白与表现使用中文改写；龙骨炮进场、后坐与开合采用简化表现；Sans 是几何像素重绘；音乐取决于平台可用资产。布局与命中细节仍需要对照实际游戏人工试玩。

离线测试已经验证流程与 API 调用约定，完整流程测试为了检查攻击时间线关闭了伤害，**不是无伤通关或人类可躲性证明**。预览使用模拟控件树或几何配方渲染，**不是官方沙箱/游戏截图**。这些限制与测试细节记录在 [审查与验证](审查与验证.md)。
