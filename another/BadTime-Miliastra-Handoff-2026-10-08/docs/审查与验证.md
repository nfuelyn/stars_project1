# 审查与验证记录

审查日期：2026-10-08。原始文件保存在 `reference/main.original.lua`，修正版导入文件为根目录 `main.lua`。所有写入与下载都位于本工作目录，父级知识库只作读取。

## 审查依据与交付结构

对照父级官方知识库、2026-09-25 的客户端资料镜像，以及 [Jcw87/c2-sans-fight](https://github.com/Jcw87/c2-sans-fight) 的 Battle.xml、Items.xml 和 24 份攻击 CSV。主要平台依据是[客户端 API](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhtakr07vej4)、[脚本与控件使用规则](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhbgxf0nynww)和[官方结算规则](https://act.mihoyo.com/ys/ugc/tutorial/detail/mhx1du08nhwo)。

原文件为五个模块合并的单文件。现在把维护源码拆到 `lua/`，新增集中配置，再由 `tools/build.py` 合并回单文件，避免正式工程依赖多份脚本映射。

| 文件 | 职责 |
| --- | --- |
| `lua/config.lua` | 难度、模板、图片、设备、音效、结算信号与重试配置 |
| `lua/core.lua` | CSV 时间线、状态机、碰撞、蓝魂、KR、物品、FIGHT 门控 |
| `lua/attacks.lua` | 从工作目录参考 CSV 生成的攻击数据 |
| `lua/fitdata.lua` | 子代理制作的自包含 CodeArt 几何配方 |
| `lua/music.lua` | 已配置的 2D BGM、短音效与可选单音回退 |
| `lua/main.lua` | 官方控件 API 适配、绘制、输入、生命周期与服务器信号 |
| `main.lua` | 构建生成的正式导入文件 |

## 已修正的问题

下面的 P1 表示会影响战斗流程、输入或结果的主要问题，P2 表示显示、兼容性或维护问题。表中均为已经修改的内容。

| 级别 | 原问题与影响 | 修改 |
| --- | --- | --- |
| P1 | `BlastTime=0` 被当作永久光束；终盘激光不断积累 | 对照参考逻辑，将该参数解释为额外停留时间；0 仍有开火、衰减和销毁过程 |
| P1 | 同一龙骨炮在 World 和 Game 两处更新，时序变快 | 删除重复更新；炮身位置、光束宽度、淡出与碰撞使用同一状态 |
| P1 | EndAttack 提前清掉 world 后再检查，结束标记失效，回合靠超时或回退生成器收尾 | 保留标记到帧末，脚本结束直接进入菜单；带脚本的回合不混入内置生成器 |
| P1 | 同一帧发生致死命中与脚本结束，失败状态又被菜单覆盖 | 命中后检查战斗状态，失败优先，不再调用回合菜单收尾 |
| P1 | 普通行动与 FIGHT 阶段进度混用，补给可能提前进入终盘 | 独立 FIGHT 计数和两阶段脚本游标；补给/检查推进下一份攻击，不推进阶段门控 |
| P1 | 中场可能被普通行动结束，或打开仁慈菜单就失败 | 中场检查、补给仍停留；只有完成 FIGHT 才继续；只有确认饶恕才触发陷阱 |
| P1 | 失败结算被转成胜利，或信号按字段名添加值不符合官方接口 | 保留 kill/spare/fail；按位置添加 7 个约定参数；区分本地发送与服务器已结算 |
| P1 | OnUpdate 与 OnLevelUpdate 同时转发会让游戏推进两次 | 默认只推进 OnLevelUpdate；单独配置外部仅 UI 更新宿主 |
| P1 | 蓝魂跳跃存在反向重力分段、额外甩击冲量和旧按住升高规则 | 参考 Battle.xml 重写分段重力与松键截断；蓝魂甩击使用统一速度寄存器；在支撑面上允许正常跳跃 |
| P1 | 骨刺保持/回缩阶段被当作无伤害 | 有实体伸出且非预告阶段时继续判定，显示与碰撞对应 |
| P1 | 控件默认 inactive、包装父层未激活；整数颜色写入 ColorValue 属性 | 实例化后激活父层与叶子；包装层拉伸归一化；颜色转为官方 Color 对象 |
| P1 | 键名以模拟器映射为依据，正式 Z/J/箭头可能无响应，鼠标可能重复确认 | 使用官方语义枚举，分别绑定实际按键；缺失的可选别名跳过；鼠标只走光标点击 |
| P2 | 多个同方向键共用布尔状态，松开 W 会取消仍按着的上箭头 | 保存每个物理按键的 held 状态，再合并方向 |
| P2 | 触摸未区分 touchId，第二触点能改变或释放摇杆；松手可能抹掉键盘方向 | 摇杆绑定所属触点；方向合并触摸与物理按键；禁用、重新启用时清理输入 |
| P2 | 引用大写 Id、按 id 缓存，和官方小写 id 不一致 | 控件缓存直接使用对象键；监听器保留原回调供卸载 |
| P2 | 模板索引匹配就当成叶子，包装模板可能误识别；调用未文档化图片字段 | 按叶子接口识别；移除图片/文本上的 raycastTarget 写入；光标区启用合法字段与宿主 showCursor |
| P2 | 把外部图元编号当作真机通用图片 ID | images 默认 0，继承模板图片；实际替换必须填当前工程资产 ID |
| P2 | 框在核心和显示层重复插值，显示边界落后于实际碰撞 | 只让核心插值，显示直接使用本帧框 |
| P2 | 池内旧控件层序固定，后来创建的激光压住灵魂和 HUD；白光束上白字难读 | 使用独立弹幕、灵魂、UI 底板与前景图层，HUD 和提示增加黑底；光标区每帧覆盖实际画布 |
| P2 | 非整数 fontSize、错误对齐字符串可能导致整帧报错 | 字号取整，使用官方对齐枚举，UTF-8 文本保持完整 |
| P2 | 蓝魂心形偏心、方向不一致；Sans 表情都回退 Default；旧炮身存在未定义颜色 | 四向像素心保持中心；头部与疲惫姿态按脚本键选择；所有炮走统一 CodeArt LOD |
| P2 | 平台外形、菜单与画面可读性欠佳；台词压住脸；结局保留旧框或被白闪覆盖 | 绿色平台、橙黄菜单边框、像素英文/数字 HUD、死亡裂心；台词上移；结局隐藏旧框并删除持续白闪 |
| P2 | 音效 ID 和音高接口被假定可用，缺少短音事件 | 2D BGM 与短音映射集中配置，默认静音；不调用未确认的音高接口；重复音限制与退出清理 |
| P2 | 额外 20 个面包混入“原作”规则 | 原作默认 8 次参考补给；额外面包仅显式开启的非原作练习档 |
| P2 | 新增适配状态后达到 Lua 单函数 200 个 local 限制 | 将新增适配状态、辅助函数集中到模块对象，合并脚本实际通过 Lua 5.3 加载 |

攻击数据已从参考项目的 24 份原 CSV 重新生成，去掉原包中针对激光宽度、停留和额外骨头的改写。保留旧解析器扩展接口用于兼容，但正式攻击以参考 CSV 为输入。生成文件中的别名是模块接口适配，不是新增攻击。

## 剩余差异与部署边界

1. **原作第二阶段的菜单骨头攻击仍未接入。** 当前玩家行动阶段会燃烧 KR，但没有原作菜单骨头造成的直接伤害。
2. **最终睡眠、推框和自动第二刀未实现。** 当前终盘结束后再次 FIGHT，经过攻击条进入击倒结局；参考 Bad Time Simulator 本身也简化了原作结尾。
3. 几何像素角色属于风格重绘，布局、对白、炮的后坐与开合简化，未宣称逐像素或逐帧完全一致。
4. BGM/SFX 取决于当前工程的合法可用资产。没有交付原作音频或确认外部音频通用导入功能。
5. 需要在游戏内建立并映射实际模板。保留的默认工程索引无法验证为用户当前工程的索引；0 音效静音是有意设置。
6. 服务器信号、结算节点图仍需按 [部署方案](部署与设置.md)手工配置。本地成功发送没有服务器回执；不适合直接作为多人权威排行榜方案。
7. 没有官方沙箱或游戏窗口的实际运行结果，也没有实体手柄验证。不得把本次离线通过写成“已在真机测试通过”。

参考项目的代码公开可查看；本次没有确认其仓库根部具有明确许可证，因此没有沿用原包里未经核实的许可断言。分发时保留参考来源，资产授权另行确认。
