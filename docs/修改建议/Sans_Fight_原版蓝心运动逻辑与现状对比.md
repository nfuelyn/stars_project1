## 0. 【优先回答】原版跳跃有没有「向上减速」？

**有。而且是三段式的。**

原版从起跳那一帧开始，**每一帧都在沿重力方向加重力**，所以上冲速度逐帧被削掉 —— 这就是"向上减速"。以重力向下（Angle=90°、`DownSpeed = dy`）为例：

| 上冲阶段 | 沿重力速度 DownSpeed | Gravity | 效果 |
|---|---|---|---|
| 刚起跳（最快） | `≤ -120`（-180 → -120） | **180** | 减速慢 → **保持冲劲**，冲得远 |
| 中段 | `-120 < v ≤ -30` | **450** | 减速快 → **硬刹车** |
| 顶点附近 | `-30 < v ≤ 15` | **180** | 减速又变慢 → **滞空、发飘** |

即：**180 → 450 → 180**。不是匀速上升，也不是"按住不放一直升"。

**原版还有一条「瞬时截断」（是砍、不是减速）：**
> **松键的那一帧**，若仍在上冲且速度 > 30 px/s → 直接把上冲速度设成 **30**。

这就是「轻点 = 小跳、按住 = 满跳」的真正来源。
**原版没有**"按住持续上升 / 上升时间窗口 0.25s / 到 3/5 框高"这类设定 —— 按住的作用**仅仅是"不触发截断"**，让上面那段三段重力把弧线走完。

**原版数值仿真（dt=1/60，纯原版公式）：**

```
满按住跳：峰值 66.90 px   到顶 0.683 s   滞空 1.267 s
松手帧数 → 峰值：
  第 1 帧 →  5.05 px      第 2 帧 →  7.95 px
  第 4 帧 → 13.60 px      第 6 帧 → 19.05 px
  第10 帧 → 29.35 px      第20 帧 → 51.60 px
  第40 帧 → 66.90 px（= 满跳；因为此时 v 已 > -30，截断不再生效）
```

## 1. 原版蓝心完整运动规则（逐条）

### 1.1 常量（Battle.xml L3037–3040）

| 变量 | 值 | constant | static | 说明 |
|---|---|---|---|---|
| `HEART_JUMP_STRENGTH` | 180 | **1** | 0 | 起跳瞬时冲量 px/s |
| `HEART_JUMPHOLD_CUTOFF` | 30 | **1** | 0 | 松键截断后保留的上冲速度 |
| `HeartSpeed` | 150 | 0 | 0 | 每帧按 Cancel 重算（按住 = 75） |
| `MaxFallSpeed` | 750 | 0 | **1** | **跨帧持久**，被 `HeartMaxFallSpeed` 改写 |

### 1.2 重力方向 = 心的 Angle（`dir*90`）

`0° = 右 / 90° = 下 / 180° = 左 / 270° = 上`。
`(X, Y) = (cos(Angle), sin(Angle))` = 重力单位矢量。

### 1.3 四个方向各自的三件事（L3811–4090）

| dir | DownSpeed 取 | 跳跃键 | 松键截断（边沿） |
|---|---|---|---|
| 0 右 | `dx` | **Left** | `dx < -30 → dx = -30` |
| 90 下 | `dy` | **Up** | `dy < -30 → dy = -30` |
| 180 左 | `-dx` | **Right** | `dx > 30 → dx = 30` |
| 270 上 | `-dy` | **Down** | `dy > 30 → dy = 30` |

跳键是**与重力反向的那个方向键**；截断只在**按下→松开的那一帧**（`按键 < 上一帧按键`）。

### 1.4 起跳 `HeartJump`（L3382–3430）

```
On function "HeartJump"  AND  PlayerHeart.Mode == HEARTMODE_BLUE:
    if HeartCheckSolid(cos(Angle), sin(Angle)) == 1:      -- 重力方向 1px 处有固体
        speed(1) -= X * HEART_JUMP_STRENGTH               -- 沿 -重力 给 180
        speed(2) -= Y * HEART_JUMP_STRENGTH
```
即"**站得住才跳**"：地面/平台/框边 1px 内有固体即可。

### 1.5 分段重力（L4051–4125，**4 个并列 IF，不是 else-if**）

```
IF DownSpeed <  240 AND DownSpeed >  15   -> Gravity = 540
IF DownSpeed <=  15 AND DownSpeed > -30   -> Gravity = 180
IF DownSpeed <= -30 AND DownSpeed > -120  -> Gravity = 450
IF DownSpeed <= -120                      -> Gravity = 180
```

⚠️ **关键**：`<variable name="Gravity" static="0">` —— C2 的 `static=0` 局部变量**每帧重置为初值 0**。
所以 **`DownSpeed ≥ 240` 时四个 IF 全不命中 → `Gravity` 保持 0 → 这一帧不加重力**。

### 1.6 施加与终端（L4144–4236）

```
if HeartCheckSolid(X*0.2, Y*0.2) == 0:        -- 前方 0.2px 无固体才加（防压进地面）
    speed(1) += X * Gravity * dt
    speed(2) += Y * Gravity * dt
    if 对应轴速度 > MaxFallSpeed: = MaxFallSpeed     -- 终端钳位（按 4 个 angle 分支）
```

### 1.7 横向（L4241–4472）

- 重力**竖直**（90/270）：先 `speed(1) = 0`（清垂直分量），再 `Left ≠ Right` 时 `dx = ∓HEARTSPEED`；并在 0.5px 偏移处与平台重叠时吸附+继承平台速度。
- 重力**水平**（0/180）：先 `speed(2) = 0`，再 `Up ≠ Down` 时 `dy = ∓HEARTSPEED`。
- `HeartSpeed = 150`；按住 Cancel = 75。**无惯性**（每帧先清零再赋值）。

### 1.8 步进

`CustomMovement`：`stepping-mode = Horizontal then vertical`，`pixels-per-step = 1`。

## 2. 原版数值仿真（实测）

| 场景 | 结果 |
|---|---|
| 满跳峰值 | **66.90 px** |
| 到顶耗时 | **0.683 s** |
| 总滞空 | **1.267 s** |
| 自由落体终端速度 | **≈ 243 px/s**（≈ 240 + 540·dt 的过冲） |

> 终端只有 ~243 的原因就是 §1.5 那个 `static=0` 死区：掉到 240 以上后不再加速。
> 也就是说**原版 `MaxFallSpeed = 750` 在自由落体里根本用不到**；它只在这两处生效：
> ① `SansSlam` 把速度**直接设成** MaxFallSpeed（甩出初速）；
> ② 终端钳位（只在脚本把 MaxFallSpeed 设成 < 243 时才有效，如 60 / 0 / -300）。

## 4. 差异影响与建议

### 4.1 【最要紧】第 6/7 条：`DownSpeed ≥ 240` 的死区

- 原版：蓝心**自由落体最快 ≈ 243 px/s**；超过 240 后重力归零，速度不再增长。
- 工作区：`> 15` 一律 540 → 自由落体一直加速到 `MaxFallSpeed`（默认 750）。
- 后果：
  - 下落手感比原版**快约 3 倍**；
  - 原版里 `HeartMaxFallSpeed` 的 330 / 450 / 480 / 750 **几乎等价**（都够不着），工作区里它们**全都有区分度** → 同一段脚本两边手感不同；
  - `sans_final` 的 `HeartMaxFallSpeed,-300 / 0 / 60 / 240` 两边行为也不同（负值/零值/小值是真实生效的，240 在原版恰好等于自然终端）。
- **若要与原版 1:1**：把 L2484-2487 改成"四个并列 IF 的语义"——
  `>15 且 <240 → 540`；`≤15 且 >-30 → 180`；`≤-30 且 >-120 → 450`；`≤-120 → 180`；**其余（≥240）→ 0**。

> 注意：这一改动会让蓝心的下落变慢很多，是**手感级**改动，建议先单独试玩 bonegap / platforms / final 再定。

### 4.2 第 12 条：slam 独立物理

原版 `SansSlam` 只做三件事：`HeartMode(BLUE)` + 设 `Angle = dir*90` + 速度**直接设成** `MaxFallSpeed`；之后**仍吃同一套分段重力**。因为初速通常 ≥ 240 → 原版那一帧起 `Gravity = 0` → 实际就是**匀速**甩到撞墙。
工作区另起一套 `GRAVITY = 600` 的加速物理（L2396-2448）。
- 当 `maxFall ≥ 243` 时两者结果接近（都到 maxFall）；
- 当 **负值 / 0 / 小值**时不同（如 `-300` 反向走廊、`0` 钉住、`60` 慢速）。
- 建议按《Sans_Fight_回合差异与蓝心物理_修改意见》§3 的方案：**合并成单一方向重力物理**，`slammed` 只保留"撞墙伤害/抖屏"用途。

### 4.3 第 10 条：跳跃键

原版的"跳"= **与重力反向的方向键**。工作区把 **UP 按下沿** 当成跳跃键，这只在"重力向下"时等价；一旦 `dir` 变成 0/180/270（`sans_final` 长框段、`bonestab` 等），原版要求按 Left/Right/Down，工作区仍按 Up。
- 若要 1:1：跳跃触发应改成"读当前 `dir` 对应的那个方向键的按下沿"。

### 4.4 第 11 条：coyote time

0.12s 的土狼时间是工作区为修"空中板子跳不起来"加的**非原版**宽容。保留可以，但要记为**有意差异**。

### 4.5 第 5 条：截断的 `jumping` 守卫

原版没有 `jumping` 标志，松键截断在任何上冲场景都会触发（包括被 `SansSlam,3` 往上甩之后松键）。工作区加了 `self.soul.jumping` 守卫 → 更合理，但与原版不完全等价。属**可接受差异**。
