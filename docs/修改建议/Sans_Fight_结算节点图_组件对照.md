## 0. 先分清三层东西（最容易搞混的地方）

| 层 | 是什么 | 在哪配 | 例子 |
|---|---|---|---|
| **信号** | 客户端 Lua 主动广播的一次性消息 | 沙箱窗口「信号配置」+ 客户端 `game.ServerSignal` | `SansFightSettle`（带 result/hp/kr/round） |

## 2. 变量清单（照抄即可）

| 变量名 | 归属 | 类型 | 初始值 | 谁写 | 谁读 | 作用 |
|---|---|---|---|---|---|---|
| `SansSettled` | 关卡(Level) | 布尔 | `false` | 节点图：收到信号后立刻写 `true` | 节点图：判重 | 保证同一次只结算一次 |
| `SettleReady` | 关卡(Level) | 布尔 | `false` | 节点图：关卡开始写 false；60 秒计时结束写 true | 节点图（做法 2）；客户端（可选） | "打满 1 分钟才能结算" |
| `SansFightResult` | 关卡(Level) | 字符串 | `""` | 节点图（可选） | 客户端/结算面板 | 记录结局类型 |
| `SansFightHP` / `SansFightKR` | 关卡(Level) | 整数 | `0` | 节点图（可选） | 结算面板 | 展示数据 |

> 类型必须和客户端发的一致：`result` = String，`hp`/`kr`/`round` = Int。
> 类型不匹配的典型症状：节点图里读出来恒为 `0` / 空串（不是报错，是静默的）。

## 3. 两种 60 秒做法的完整连线（组件级）

### 做法 1（推荐）：关卡开始起计时

```text
[关卡开始事件]
      │
      ├─► [设置自定义变量] Level.SettleReady = false
      │
      └─► [计时器 60s] ──► [设置自定义变量] Level.SettleReady = true
                              └─(可选)─► [显示提示 / 播放音效] "现在可以结算了"

—— 另一条线：客户端点「结 算」 ——
[收到服务器信号 SansFightSettle]
      └─►（走 §1 的判重 → 判胜负 → 展示数据 → 结算关卡）
        （若还想服务端兜底，可在判重前加：查询 Level.SettleReady，为 false 则忽略）
```

### 做法 2：收到信号时再判时间

```text
[收到服务器信号 SansFightSettle]
      │
      ├─► [查询变量] Level.SettleReady
      │        ├─ true  ──► [判重] → [判胜负] → [展示数据] → [结算关卡]
      │        └─ false ──► [设置变量] Level.SettleTooEarly = true（或直接忽略）
```

差别：做法 1 客户端能"提前知道"按钮该不该出现（读 `SettleReady`）；做法 2 按钮一直在，是否结算由服务端说了算。

## 4. 引脚连线顺序速查（照这个顺序连，不会错）

```text
事件(收到信号) ─► 判重(查询变量) ─► 写标记(设置变量) ─► 分支(比较+分支)
      ─► 设置玩家结算状态 ─► 设置结算展示数据 ─►(可选 设置排名)─► 结算关卡
```

- "查询类"节点（比较、读变量、取列表长度）**不串执行流**，只把输出引脚接到需要它的输入引脚；
- "执行类"节点（设置变量、设置状态、展示数据、结算关卡）**必须首尾相连**，顺序就是执行顺序；
- 拿玩家实体：`获取在场玩家实体列表` →（列表长度 == 1）→ `获取列表元素(索引 0)` → 玩家实体，再接到「设置玩家结算状态」的玩家引脚。

## 5. 排错对照表

| 症状 | 最可能的原因 | 怎么查 |
|---|---|---|
| 节点图完全没被触发 | 信号名不一致 / 只声明没连"收到信号"节点 | 客户端日志有没有 `main: 已发送结算信号 SansFightSettle`；沙箱窗口信号面板里名字逐字符核对 |
| 触发了但 `hp/kr/round` 全是 0 | 信号参数**类型**不匹配（Int 声明成 String 等） | 信号配置里逐项对类型；节点图上把参数打印出来看 |
| 结算了两次 | 信号是全局广播，监听了多处；或缺去重变量 | 只留一处监听 + `SansSettled` 判重 |
| 结算面板没数据 | 展示数据在「结算关卡」之后才写 | 顺序改成：状态 → 展示数据 → **最后**结算关卡 |
| 玩家实体为 null | 把控制物件/3D 角色实体当成了玩家实体 | 用「获取在场玩家实体列表」取 |
| 客户端读 `SettleReady` 一直是 false | 变量归属选成了"玩家"而不是"关卡(Level)" | 读/写两边的归属要一致 |

## 7. 追问：`SansSettled` 这种自定义变量**不声明/不设置**能不能直接读？

**不能依赖"直接读"。** 未声明的变量在不同宿主/版本上有两种行为，都会踩坑：

| 宿主/位置 | 未声明时读到的 | 说明 |
|---|---|---|
| 沙箱模拟器（`client/lua-runtime` 实现） | `nil` | `getVar()` 取不到就返回 undefined → Lua 侧是 nil，**不会报错但你也分不清"没结算过"和"变量不存在"** |
| 官方真机（按我们工程的处理口径） | 可能**直接报错** | 所以本工程所有读变量的地方都用 `pcall` 包住（见 `lua/main.lua` 的 `difficulty()` / `bootRound()`：`pcall(function() return game.GetGlobalCustomVariableValue('Level', …) end)`） |
| 节点图「查询自定义变量」节点 | 视版本：给类型默认值（布尔=false）**或**提示变量不存在 | 同样不可靠 |

### 7.1 正确做法（三步，推荐）

1. **先声明**：沙箱窗口 →「自定义变量」面板 → 新建
   `归属 = 关卡(Level)`、`变量名 = SansSettled`、`类型 = 布尔(Bool)`、`默认值 = false`。
2. **关卡开始时强制写一次 false**（★ 比"能不能读"更容易踩的坑）：
   `[关卡开始 / 玩家进入] → [设置自定义变量] Level.SansSettled = false`
   原因：**关卡变量会跟着关卡存档持久化** —— 上一次结算写进去的 `true` 会留在存档里，
   下次进关如果不在开始时复位，就会"永远结算不了"。
3. 收到信号后按 §1 的顺序：`查询 SansSettled` → `true 就结束` / `false 就写 true 并继续结算`。

### 7.2 如果就是不想声明变量：三种替代

| 替代 | 怎么做 | 适用 |
|---|---|---|
| **执行一次类节点** | 「收到服务器信号」后面接一个 `仅执行一次 / Once / 执行一次` 节点，第二次触发被它吞掉 | 编辑器里确有该节点时，最省事（不需要任何变量） |
| **结构性去重** | 收到信号 → 先把挂节点图的那个服务端控制物件**设为不可用**（或断开这条监听）→ 再走结算 | 不需要变量；适合"一次结算后整关就结束"的场景 |
| **Lua 侧容错读** | `local ok, v = pcall(function() return game.GetGlobalCustomVariableValue('Level','SansSettled') end)`；把"读不到"当 false：`if ok and v == true then 已结算 → return end` | 只在客户端脚本里用；**不能**替代节点图的去重 |

### 7.3 一句话总结

> 变量不是"读之前会自动创建"的东西 —— **要么先声明（并在关卡开始复位），要么干脆不用变量**（改用执行一次节点 / 结构性去重）。

## 8. 追问：**自定义变量** 和 **节点图变量（图变量）** 的区别

一句话：**自定义变量 = 关卡/玩家级、跨系统共享、会随存档保存；节点图变量 = 某一张图自己的局部变量、别的图和 Lua 都看不到、不进存档。**

| 维度 | 自定义变量（关卡的 `Level.*` / 玩家 `Player.*`） | 节点图变量（图变量，图内 `变量` 面板） |
|---|---|---|
| 作用域 | 整个关卡（或某个玩家/实体），**全局** | **只属于当前这张节点图**（别的图看不见） |
| 谁能读写 | 节点图节点、**客户端 Lua**（`game.GetGlobalCustomVariableValue`）、UI/结算面板等 | 只有**这张图自己**的节点 |
| 生命周期 | 随关卡走；**会写进关卡存档**（重进可能还是上次的值） | 图重置/关卡重进就回到初始值；不进存档 |
| 需要先声明吗 | **要**（在沙箱「自定义变量」面板里建：归属+名字+类型+默认值） | 在图变量面板里定义（同样是"先声明后用"，但只在这张图里） |
| 初始值 | 声明时给默认值；**实际值可能被上次存档覆盖** → 关卡开始要复位 | 每次进图都是你设的初始值，**没有残留问题** |
| 跨端能力 | 服务端权威、客户端可读（我们用它做"客户端 ↔ 服务端"沟通） | 纯服务端内部，客户端读不到 |
| 典型用途 | 难度覆盖 `SansDifficulty`、调试跳关 `SansRound`、`SettleReady`（客户端要读）、跨图共享的状态 | 循环计数、临时状态、**同一张图内的去重** |

### 8.1 落到我们工程里的选型

| 变量 | 建议用哪种 | 为什么 |
|---|---|---|
| `SansDifficulty`、`SansRound` | **自定义变量（Level）** | 客户端 Lua 要读（`lua/main.lua` 的 `difficulty()` / `bootRound()` 都在读它们） |
| `SettleReady`（60 秒门槛） | **自定义变量（Level）** | 客户端将来要读它来决定"结算按钮什么时候出现" |
| `SansSettled`（结算去重） | **两种都行，看它要不要出这张图**：<br>• 只在"收到信号"那张图里判重 → **优先用节点图变量**（天生有初始值、不受存档残留影响、不用在关卡开始复位）<br>• 需要被别张图或 Lua 读 → 用自定义变量，并**在关卡开始强制写 false** | 见 §7 的坑：自定义变量会残留 `true` |

### 8.2 三个常见坑

1. **自定义变量会跨存档残留**：上次结算写的 `true` 会留在关卡存档里 → 下次进关"永远结算不了"。**解决**：`[关卡开始/玩家进入] → 设置 Level.SansSettled = false`。
2. **图变量读不到 ≠ 变量不存在**：图变量只有本图能用；如果你在另一张图或 Lua 里读它，永远读不到（且没有任何报错）。
3. **同名不等于同一个东西**：`Level.SansSettled`（自定义变量）和某张图里的图变量 `SansSettled` 是两个互不相干的变量；命名上建议区分（例如图变量叫 `graph_settled`）。

### 8.3 选型速查（三问定夺）

```text
① 客户端 Lua 或别的图要读它吗？        要 → 自定义变量；不要 → 可以用图变量
② 需要跨"重进关卡"保留吗？            要 → 自定义变量（并在需要时手动复位）；不要 → 图变量更安全
③ 只是某串节点的临时记账/去重吗？      是 → 图变量（最省事，没有残留坑）
```
