### 2. 攻击模板

- **27 个攻击脚本逐字转写**自仓库 `Files/sans_*.csv`（脚本骨锚点、批量骨排列 `X = StartX - cos(dir*90)*Spacing*i`、SineBones 公式、骨刺形状、龙骨炮飞行/旋转/开火全部对齐）
- **固定编排（P-02）**：整场改为仓库 §1 总表的原作序列，`TOTAL_ROUNDS = 24`（0..22 攻击 + 23 终盘 `final`），中场 = 第 13 次 FIGHT
- **高骨公平性**：高骨降高（46/95/107 → **32**，底沿严格低于跳跃最高点）+ **跟在矮骨后面进场**
- **骨缝加宽**：`sans_bonegap2` 上下骨缝 18 → **30px**
- **右侧骨头让路**：`platforms2/3` 里「地面必中」的那几根，按「底沿 ≤ 落脚带 − 余量」削短
- **箭头模块统一模板**：`HeartWall`（贴墙模式，不走普通蓝心物理）+ `SansSlam`（真的把灵魂拖到框边）+ `ArrowBone`（**整条边升起一排骨头**，伸出 `min(1/4 框宽, 3/5 框高)`）+ 跳跃 = **箭头反方向冲刺**
- **龙骨炮延时**：首轮 `SpinTime` 1.0s；14 回合 1.5s + `HoldTime` 2.5s；多段攻击四角交叉 2.0s
- **平台加速**：`platforms4/4hard` 从 0 加速到全速（作者 readme 自述的 Known Issue）
- **幽灵平台**：`blue_soul` 回合只有不带脚本时才造内置平台

### 3. 蓝魂物理（多轮迭代到最终值）

| 项 | 最终值 |
|---|---|
| 上升 | 按住 → 匀速，速度 = `0.6 × 框高 / 0.25s`（140 → 336px/s），**0.25s 到 3/5 框高** |
| 上升窗口 | 只有 0.25s：按住超过也停，然后**自然下落**（不再悬停/浮空） |
| 下落 | 匀速，`0.5 × 框高 / 0.75s`（140 → 93.3px/s） |
| 二段跳 | 松手即剪断本次跳跃，下降途中再按不会回升 |
| 平台起跳 | coyote time 0.12s + **站上平台被平台带走**（按当帧速度），保证移动平台上能起跳 |
| SansSlam | 独立冲量 `soul.push`，红/蓝/贴墙三模式统一积分（实测 dx=±136 / dy=122） |
| 权威源 | `Game.soul` 唯一权威；`World.heart` 降级为脚本寄存器（G5） |

### 4. 流程与时长

- **真实时长**：新增 `World:simulateLength()` 干跑求脚本真实秒数，`enemyDur` 取 `max(静态, 干跑)` —— 终盘从 **8.02s 修到 53.03s**（原来 85% 内容从没播过），`bonestab3` 5.27→26.55、`spiral1` 0.09→10.58
- **EndAttack 立即收尾**：留 0.2s 淡出即 `endEnemy`，`enemyDur` 降级为安全上限
- **回合计数（B-01）**：拆成 `round`（攻击序列，每次行动 +1）与 `fightCount`（**只数 FIGHT**），阶段门控与原版 `HitAttempts` 同口径
- **难度接入脚本（G3）**：`tune` 传进 `World`，`spd/itv/wn` 缩放速度/间隔/预警；「原作」档改成真原值 1.00/1.00/1.00
- **心速（V-03）**：260 → **150**（按住取消键 75）

## 二、不好实现 / 做不到的地方（重要，请先读这一节）

### A. 原版数据不可得（只能在近似与仓库自述之间取舍）

1. **心判定盒的精确尺寸**：仓库 `Textures/` 里没有 PlayerHeart 贴图，作者 readme 自己就写 `Heart hitbox is probably not accurate`。我们只能按代码里真正的判定物 `PlayerHitbox` = **4×4** 来设，无法 100% 还原原作手感。
2. **KR 的逐帧曲线**：仓库只给了上限 40 与「保底 hp>1」，没有每帧燃烧速率表。我们维持 0.5s/点并加断言，属于合理近似而不是逐帧还原。
3. **原作《Undertale》里的随机点/帧数据**：本仓库是固定编排（已照抄），但原作真正的随机点与帧数据不在这里，只能以本仓库为准。
4. **激光尺寸/伤害/Karma 的原作值**：`GasterBlast1/2/3` 的 `BaseSize/SineSize` 是反编译近似；我们沿用仓库值（20/36/56）与 1/10 Karma。
5. **撞击伤害阈值 >330**：我们的蓝魂是**匀速模型**（没有冲量式 slam），这条阈值不适用；要还原就得把蓝魂改成速度+重力模型，会推翻现有手感 —— 未做。

### B. 原工程自身的缺陷（我们选择不照抄）

6. **Practice 模式不可用**：原工程里 `SetPracticeAttack` 被 `System.Is in preview` 限制、预览初始化事件被 disabled、且每 tick 覆盖 `NextAttack` —— 三重问题。**按你的指示本项目不做 Practice**。
7. **`*Repeat` 丢参数**：原版 `BoneVRepeat/BoneHRepeat` 不传 Color、`PlatformRepeat` 不传 BooleanReverse（所以原版做不出「重复生成的蓝骨/反弹平台」）。我们**加了可选第 8 参**作为本项目扩展。
8. **`GasterBlaster Size=0` 不设高度**：原版会继承上一发的高度。我们的尺寸表是全显式的，不会踩这个坑。
9. **玩家侧平台碰撞分支被禁用**：原版把「平台侧面碰撞」与「左右重力下平台带走」两个分支都 disabled。侧面碰撞我们按原版**关掉**；但**平台带走按你的要求打开了**（否则移动平台上跳不起来）——这是一处有意的项目差异。
10. **三关骨刺统一模板**：第二轮文档 G12 建议还原 `bonestab1/2/3` 的差异参数，但你此前明确要求统一一套战斗模板，因此**保留统一** —— 也是一处有意差异。

### C. 运行环境/平台层面的硬限制

11. **真机未验证**：所有证据来自离线回归 + 模拟器（studio）试玩，**从未在千星真机跑过**。
    - GIA 导出**不保存脚本挂载关系**，导入真机后必须**手工把 boot 重新挂到 `n1`**；
    - 客户端需要 7 个图元模板预先存在（`verify-client-pool.mjs` 校验契约）。
12. **客户端不支持 `require`**：4 个 Lua 源文件必须**内联成一条自足脚本**，存档因此约 350KB。
13. **按键转发依赖试玩页/插件**：WASD/方向键/摇杆的语义映射曾因插件缓存旧字节而失效（必须重启 `dsh web`），这类问题改代码解决不了。
14. **双坐标系仍是历史包袱**：世界帧（① 640×480 绝对）与框内相对帧（②）靠 `BOX_OFF = (240,226)` 换算，G5 之后 `Game.soul` 成了唯一权威，但 `BOX_OFF` 仍散落在多处；彻底统一要重写整层坐标，风险高、收益低。
15. **`spiral1/2/3` 变成「死脚本」**：固定编排里这些位置被 bonestab/multi 占用，旋转光束现在只在终盘 `final` 里出现；三个脚本保留为终盘分档/调试素材（G11 已标注）。

### D. 已知的性能/工程取舍

16. **干跑求时长有开销**：每回合开始会跑一次 `simulateLength()`（纯逻辑、不渲染），约 1~2s CPU；目前**没做缓存**，回合切换可能有短暂卡顿。要优化可在 `attacks.lua` 里预存每条脚本的实测时长。
17. **必须重建存档才生效**：改任何 `.lua` 后不跑 `node tools/build-save.mjs`，试玩页还是旧逻辑（判据看日志里的 `build=` 标记）。
18. **难度是设计不是原作**：简单/普通/困难三档倍率（0.60/0.78/1.00 等）是本项目加的；只有「原作」档 = 1.00 才是原值。
