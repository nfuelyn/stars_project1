## 3. 为什么会变成「必定受到伤害」

### 3.1 满跳 66.9px，而 h=100 的骨需要抬升 99px —— 算术上过不去

用真实物理实测（同一套 `Game` + `core` 的蓝心物理，`lua/_probe_jumpnum.lua`）：

```
框高 140  轻点跳高 10.3px  满跳(按住) 66.9px
```

- 这一段框高 115，灵魂贴地时心中心 y=383、**判定体半宽 SOUL_R = 2**（`M.SOUL_R`）。
- 要"从高骨上方飞过"，判定体下沿必须高于骨顶：`soul.y + 2 < 骨顶 y`
  - h=100 骨顶 y=286 → 需要 `soul.y < 284` → **需抬升 99px > 满跳 66.9px ⇒ 不可能**
  - h=45 骨顶 y=341 → 需抬升 42px ⇒ **可以**
  - h=20 骨顶 y=366 → 需抬升 17px ⇒ **可以**
- 也就是说：**h=100 的骨只要扫到灵魂所在的那一列，玩家怎么按都会被打**。这就是"越轴 = 必中"的算术依据。

### 3.2 蓝骨要"静止"、矮骨要"起跳" —— 两个要求互相矛盾

- 蓝骨 `Color=1` 的语义（`core.lua:2778-2779`）：**只在灵魂"正在移动"时扣血**（对应原版 `Battle.xml` 的 `Attack9Patch.Color=1` + `PlayerHeart Is moving` 分支，见附录 B）。
- 矮骨 h=20 贴地：**只有起跳能躲**（起跳 = 按方向键 → `moved=true`，`core.lua:2466`）。
- 时间窗（原作难度、1.1s 段长）：

| 事件 | 时刻 | 说明 |
|---|---|---|
| 蓝骨（东，生成 x=128）扫到灵魂列 | t = (323.5−128−10)/240 ≈ **0.77s** | 蓝骨此刻与灵魂重叠 |
| 蓝骨完全离开灵魂列 | t = (323.5−128+4)/240 ≈ **0.83s** | 之后不再重叠 |
| 矮骨（东，生成 x=56）扫到灵魂列 | t = (323.5−56−10)/240 ≈ **1.07s** | 最后 0.03s（段末 1.1s 清场） |

→ **只有 0.83s～1.07s 这 0.24s 的窗口允许起跳**。放风筝/连跳/落地误差都会落进蓝骨的重叠期 → 掉血。这是"体感必中"的第二个来源（原版同样很紧，但原版的灵魂判定体、落地手感与这里不同，所以这边更难）。

### 3.3 原版凭什么不会"越轴打人"

1. **原版骨头的寿命 = 段长**：`BoneV/BoneH` 属于 `Attack9Patch` 家族（`.caproj` L1017-1036），而 `BlackScreen(1)` 会销毁该家族全部成员（`Battle.xml` L1556-1577：`Destroy AttackSprite` + `Destroy Attack9Patch`）。每段开头 `BlackScreen,1` 一到，**上一段的骨头整体消失**。
2. 因此**飞行距离 = 速度 × 段长**：
   - Attack0：240 × 0.9 = **216px**；东侧高骨 64 → 280（前缘 290，距中轴 −33.5px）；西侧 576 → 360（距中轴 +36.5px）→ **不越轴**。
   - Attack1：240 × 1.1 = **264px**；东侧白骨 24 → 288（前缘 298，距中轴 −25.5px）；蓝骨 128 → **392（越轴 +68.5px）**。
3. 结论：**原版本来就允许"蓝骨越轴"**（蓝骨靠"别动"通过），但**白骨高骨永远停在离中线 25~33px 的地方**。本端口虽然照样在 `BlackScreen(1)` 清场（`core.lua:812-819`），但骨速与段长**都乘了难度倍率**（`w:spd()`=`速度×tune.speed`、`w:itv()`=`时间×tune.interval`，`core.lua:1020-1021、554`），普通档合起来是 **×1.053**：
   - 东侧白骨 24 → 288×1.053 ≈ **302**（前缘 312）→ **正好贴上灵魂视觉左缘（312），离判定体（318）只剩 6px**；
   - 任何一次"骨速不再吃难度倍率 / 段长再拉长一点"的改动，都会立刻把它推过中线 → **变成必中**。
   - 这就是"消失时间只在主程序按文档改过之后才错"的真实机制：**余量被吃光**，不是延时本身。

## 4. 修改方案

### 4.0 方案选择

| 方案 | 内容 | 影响面 | 建议 |
|---|---|---|---|
| **A（按你的口径，推荐）** | 给 **Attack0 / Attack1 的全部侧骨**加"中轴引信" | 只动 multi1/multi3 这 16 行 | 本文主推：**整组到中线前消失**，中线上留出安全区 |

| C（不推荐） | core 里按"高 + 贴地 + 横移进场"自动判定 | 会波及 `sans_bluebone`(HUD3)、`platforms1/2` 等 | **不要用**：`platforms1.csv:15` 的 h=95 是"从上面扫、要蹲着躲"的骨，自动规则会误伤（它的底沿 352 < 贴地线 383，本来就不该判定为"不可跳越"） |

> 方案 A 的副作用要写清楚：整组都在中线前消失后，**"心停在中线附近 ±14px"就是这段的安全位**（安全区宽 28px）。这是你明确要的"防止必定触碰灵魂"；若你希望矮骨仍必须跳，就选方案 B。

### 4.1 规则定义（中轴引信 MidFuse）

对**带 MidFuse 标记**、且**横移**（`vx≠0, vy=0`）的竖骨：

```
cx    = (zone.l + zone.r) / 2          -- 战斗框水平中线（本段 = 323.5）
KEEP  = 16                             -- 引信余量 = 灵魂视觉宽（2×SOUL_CLAMP）
东行 (vx>0)：前缘 = b.x + b.w；  当前缘 ≥ cx − KEEP  → 立即销毁
西行 (vx<0)：前缘 = b.x     ；  当前缘 ≤ cx + KEEP  → 立即销毁
```

- 只对**显式标记**的骨生效 → 其它 22 个脚本零影响（不越权改动）。
- 与灵魂的安全距离（灵魂停在中线贴地时）：东行骨销毁时右缘 = cx−16，灵魂判定体左缘 = cx−2 → **净空 14px**；视觉心左缘 cx−8 → **净空 8px**。所以"看得见的骨"和"打得中的判定"都不会碰到中线上的灵魂。
- 帧步误差：最快 360px/s（Attack4 那一类）一帧走 6px，`KEEP=16` 完全吃得下。

**KEEP 取值的取舍**

| KEEP | 中线安全区宽（2×(KEEP−SOUL_R)） | 说明 |
|---|---|---|
| 12 | 20px | 视觉心（16px）几乎必须正中，手感偏严 |
| **16（推荐）** | **28px** | 与灵魂视觉宽一致，心大致压在中线即可 |
| 24 | 44px | 更宽松，但骨头会在离中线 24px 处就"凭空消失"，观感偏怪 |
