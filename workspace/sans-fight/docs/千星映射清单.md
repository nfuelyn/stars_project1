## 六、输入映射

### PC

| 物理键 | 语义事件 |
|---|---|
| `W` / `↑` | `KeyboardMoveForwardKeyDown/Up` |
| `S` / `↓` | `KeyboardMoveBackwardKeyDown/Up` |
| `A` / `←` | `KeyboardMoveLeftKeyDown/Up` |
| `D` / `→` | `KeyboardMoveRightKeyDown/Up` |
| `Enter` / 小键盘回车 / `Space` / `Z` | `KeyboardMenuConfirmKeyDown/Up`（试玩页）**或** `ControllerMenuConfirmKey` / `KeyboardJumpKey` / `KeyboardNormalAttackKey`(J) / `KeyboardInteractKey`(F、E) |
| `J` | `KeyboardNormalAttackKeyDown/Up` |
| `Esc` / `X` | `KeyboardMenuBackKeyDown/Up` |

蓝魂跳跃键是确认键（不是单独的 `JumpKey`）；确认/取消都是**多来源聚合**，任一来源按住即算按住
（真机枚举里没有 `KeyboardMenuConfirmKey`，细节见 §十四 / `docs/device-setup.md` §2.4）。
真机上这些事件名必须换成 `Enum.KeyEventType.*` 枚举项才能注册，适配层会自动回落。

### 触摸

- 使用 `全屏光标区` 的 `CursorDown / CursorDrag / CursorUp / CursorClick`
- 左半屏拖动 = 摇杆
- 点按选项 = 第一次选中，第二次确认

## 十四、真机接口类型（2026-10-08 真机日志实测）

真机（PC，`canvas=1600x900`）跑 `build=2026-10-08-sandbox-adapter` 的日志给出了三条**接口类型**事实，
以及一条销毁期限制。适配层已按这些事实改成「先字符串、抛错再枚举」的双通道，模拟器与真机共用同一段代码：

| 真机报错 | 事实 | 适配层做法 |
|---|---|---|
| `bad argument #2 to 'AddKeyEventListener' (KeyEventType expected, got string)` | 真机的按键监听第 2 参**必须**是 `Enum.KeyEventType.*` 枚举项 | `G_REAL.addKeyEvent`：先用字符串注册（模拟器/试玩页注入的就是字符串），抛错再把同名 `Enum.KeyEventType.<name>` 注册一次；返回真正生效的键，`OnDestroy` 用它摘 |
| `bad argument #2 to 'AddCursorEventListener' (CursorEventType expected, got string)` | 指针监听要 `Enum.CursorEventType.*` | `G_REAL.addCursorEvent`，同上 |
| `bad argument #2 to 'horizontalAlignment' (TextHorizontalAlignment expected, got string)` | 文本框对齐要 `Enum.TextHorizontalAlignment.*` | `G_REAL.setAlign`：第一次先试字符串，被拒就**永久切到枚举**（只探测一次，不会每帧白抛） |
| 警告：`客户端控件生命周期处于创建或销毁时，无法调用 DestroyClientUIControl` | 销毁阶段**不能**主动销毁控件 | `OnDestroy` 只摘监听 + 清引用；自建控件挂在宿主 root 下，容器销毁时引擎一并回收 |

### 14.1 确认键：真机枚举里**没有** `KeyboardMenuConfirmKey`

`worker.js` 的 `pl()`（`Enum.KeyEventType`）里键盘项只有
`KeyboardMoveForward/Backward/Left/RightKey`、`KeyboardJumpKey`、`KeyboardDropKey`、`KeyboardInteractKey`、
`KeyboardNormalAttackKey`、`KeyboardCharacterSkill1..4Key`、`KeyboardCraftspersonKey1..43`、`KeyboardSwitchToWalkOrRunKey`、
`KeyboardSprintKey`、`KeyboardOpenShortcutWheelKey`、`KeyboardNone` ——
**`MenuConfirmKey` / `MenuBackKey` 只在控制器项里**（`ControllerMenuConfirmKey` / `ControllerMenuBackKey`）。

所以「确认」在真机上不能只绑 `KeyboardMenuConfirmKey`，适配层改成**多来源聚合**：

| 动作 | 绑定的来源（各自 Down/Up 都注册） |
|---|---|
| 确认 | `KeyboardMenuConfirmKey`（试玩页）/ `ControllerMenuConfirmKey` / `KeyboardJumpKey` / `KeyboardNormalAttackKey`（J）/ `KeyboardInteractKey`（F、E） |
| 取消 | `KeyboardMenuBackKey`（试玩页）/ `ControllerMenuBackKey` / `KeyboardDropKey` |

- 任一来源按住 = 按住（`confirmHeld` 用来源表聚合）——**一个来源的抬起不会顶掉另一个还按着的来源**，
  蓝心长按跳跃的高度才不会忽高忽低。
- 枚举里不存在的来源（真机上的 `KeyboardMenuConfirmKey`）只打印一句「跳过可选键」，不是错误。
- 模拟器/试玩页仍然走字符串键（WASD/Enter 都能用），两条路径并存。

### 14.2 真机自检该看到什么

```text
main init: root=true canvas=1600x900 scale=1.875 ox=200.0 oy=0.0
main: 检测到真机模板，跳过大批量预热，改为按需创建控件     ← 真机模板=容器包装，按需创建才不卡
main: 跳过可选键 KeyboardMenuConfirmKeyDown（本宿主不认字符串键名，枚举里也没有这一项）
main start: build=2026-10-08-sandbox-adapter device=KeyboardAndMouse touch=false mode=core pool=4 …
```

`pool=` 在真机上很小（个位数到几十）是**正常的**：预热被主动跳过，控件按需创建。
**不应该**再出现：`main: draw ERR`、`bind fail`（方向键）、`main: 游标监听注册失败`、
`无法调用 DestroyClientUIControl`。

模拟器侧的等价断言（不依赖真机）：`node tools/run-lua.mjs lua/probes/_probe_sandbox_adapter.lua`
→ 期望 `PASS 48 / FAIL 0`（含「真机只吃枚举」的严格替身：字符串一律抛错，必须回落到枚举）。
### 14.3 确认键还是没反应？用键位诊断

`lua/config.lua` 设 `C.keyDiag = true`（改完重建存档）→ OnStart 把 `Enum.KeyEventType` 里所有事件都挂上
「按到就打印」的监听（日志先打 `main: [keyDiag] 已挂 <N> 个按键监听`）。然后在关卡里按你打算用作确认的
键，日志会打 `main: [keyDiag] <事件名>`；把事件名写进 `lua/main.lua` 的 `bindKeys()` 候选表即可。
诊断完改回 `false`。
### 14.4 锚点 / pivot：黑底只黑左下角的根因

真机模板默认锚点/pivot 是 Unity 的 (0.5,0.5)，而 `put()/putRot()` 按「锚点+左下角」口径摆图 →
黑底（3 倍画布、位置 `(-CW,-CH)`）被当成「中心在左下」，只剩左下角是黑的，其它图元整体偏移。

修法：`instantiateTemplate` **无条件**归一化（轴对齐件 `(0,0)`；rot/rtri/bakedC `(0.5,0.5)`；
cursor/bakedRoot 拉伸铺满），`OnStart` 把宿主 root 也拉成铺满画布，图片叶子清掉
`enableMask/enableSoftEdge/enableFill`。详见 `docs/device-setup.md` §2.5。

> `C.images = nil/0` 是**沿用模板自带图片**、不调 `SetImage`（交接包 `config.lua` 同样全 0）。
> 真机日志 `baked sans_body_default … rects=295` 说明 CodeArt 配方在正常生成 —— 问题不在图片资源。
